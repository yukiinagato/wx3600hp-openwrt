# TTL 接线与恢复

## 已验证板子的补件记录

用户在本次实机上 **用焊锡短接了 R53、R54、R28，R28 在 PCB 的另一面**，之后完成双向串口操作。此前能接收到启动日志但无法中断启动；USB-TTL 的 TX 指示灯未亮，适配器回环测试也参与了排查。

这是该板的实际改动记录，**不是“RXD/TXD 应该直接短路”的意思**，也不代表所有硬件版本都应将这些位号改成 0Ω。确认板号、位号、焊盘去向与电压后再操作；不要凭外壳方向猜针序或凭“测到了阻值”认定 RX 信号已经连通。仓库没有发布能可靠标注全部位号的通用板图，因此不提供猜测的照片针序。

## 三根线，交叉收发

先断开路由器电源，确认适配器是 **3.3V TTL 逻辑**，不是 RS-232，也不是 5V TX。

| USB-TTL | 路由器 UART |
|---|---|
| GND | GND |
| TXD | RXD |
| RXD | TXD |
| VCC / 3V3 / 5V | **不连接** |

路由器用自己的电源供电；USB-TTL 只收发信号并共地。**不要把路由器 RX 与 TX 短接，不要把 VCC 接上，不要短接电源/地。** 换线、焊接、测电阻时先断电。不要用焊锡跨接不明确的焊盘。

串口参数：`115200 baud, 8 data bits, no parity, 1 stop bit`，关闭硬件流控与软件流控。上电前打开监听，记录从第一行开始的完整启动日志。

## 只有日志，没有键盘输入

1. 路由器断电，将三根信号线从路由器断开。
2. **仅在 USB-TTL 适配器自身**将 TXD 与 RXD 相连做回环；发送测试字符串，应收到原样回显（关闭终端本地回显）。这一步的短接与路由器焊盘无关。
3. 如果 TX 灯不闪或无回显，先检查串口设备、线材、适配器和流控；不要继续改路由器电阻。
4. 回环成功后恢复三线交叉接法，检查路由器 RX 路径，包括本次板上 R53/R54/R28 的实际连通。TX 指示灯闪只能证明适配器发送了数据，不能证明 SoC 收到。
5. 保持监听，重新上电，在启动器的实际中断窗口发送空格；本机存在第二个中断窗口，不能只等 Linux 启动再敲键。

## 进入启动器后的原则

先保存日志和当前环境，不要执行菜单里会写闪存的“下载/升级”项。TFTP 菜单不一定是 RAM 启动，部分选项会直接擦写。此机启动器支持 `boot_system1`，实机曾由此临时进入保留的原厂槽：

```text
run boot_system1
```

只在确实看到对应 U-Boot 命令提示符、确认该环境变量存在时使用。不要直接抄用别的型号 NAND 地址，也不要为了修复 System2 擦除 BL2/FIP/Factory/bootseq。

从原厂 System1 取得 shell 后，先备份/读回损坏槽，确定是 DT、脚本、CRC、PHY 初始化还是内核崩溃。需要改 System2 时，重新进入纯 RAM 安装环境并使用受限写入器。原厂 System1 的内核与只读根保留，不意味着所有机子的原厂 SSH 已经配置好；不可用时串口仍是恢复渠道。

`NONRST_REG2` 的保护对暖重启有帮助，但不承诺所有掉电/启动死循环都能自动恢复。未完成冷启动验证前，不应收起串口恢复工具。
