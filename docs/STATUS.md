# 验证状态与已知限制

更新：2026-10-28。区分“原机成果”与“这次公开整理的通用构建”。

## 原机已完成

- stock 1.5.3 认证配置入口、Telnet root shell、密钥 SSH、ECC 主数据和全部逻辑分区备份。
- 原厂 DMA 停止、EL1 跳板、分阶段 RAM 启动；随后双核/512MiB、WAN 2.5G、双频 MT7915、LAN 和 IPv4/IPv6 通过。
- 新内核修复 RTL8221B 缺少 probe 的空指针路径；正确使用交换机内部 MDIO。
- System2 写入逐块/整槽回读、保留签名校验、软件重启、用户实际断电至少 10 秒冷启动、UBIFS 配置持久性。
- 原厂 System1 保留；保守按钮原厂侧 → OpenWrt 的实体操作已测，启动选择断电保留。故障恢复曾使用 TTL。
- Br/Rt 配置、LuCI、面板/网口灯、UPnP 映射、IPv6 与 Br Guest VLAN 做过功能测试。部分配置是后续 overlay 修改，不在早期基础镜像里。

负载测试中曾出现 WAN 物理链路断开约一分钟再恢复；根因未唯一确定。不能宣称所有交换机组合和持续双向 2.5G 负载均稳定。Wi-Fi 测试曾受手机低电量模式、空间流和测试方法影响，不发布没有可复现证据的“满速”数字。

## 公开整理后的检查

- C 启动记录测试：空白/双槽/新旧序号/损坏拒绝/序号回绕。
- Python 离线测试：CRC 四字节修正、bootseq 解析、FDT 保留、合成 FIT 增加脚本、个机校准/地址注入、配置加密往返、RAM cpio 入口、分区边界。
- ARM64 RAM loader、受限写入器、选择器、守护、面板与 PHY 工具编译。
- 四种 DTS 已用本次参考内核头文件和 dtc 实际编译。
- 用私有原厂备份运行新 FDT/封装逻辑，并用实际 FIP 的公钥独立验签通过；测试输入未公开。
- 完整 OpenWrt 源码组件构建与 GitHub Actions 的最新结果以仓库运行记录为准；CI 不连接实物，也不自动写入任何设备。

**公开通用脚本尚未在第二台设备上做完整免拆机首装/掉电恢复测试。** 没有可直接上传 OEM 网页的 release image。设备树从个机内嵌数据改为编译后从自己 Factory 注入；新编译的软件包、feeds 和 initrd 与原机运行的后续 overlay 并非逐字节相同，必须再次 RAM 测试。

## 未完成 / 明确不支持

- OpenWrt 上游合入和标准 factory/sysupgrade 支持。
- 其他原厂版本、启动器/板号、坏块较多设备的通用安装保证。
- 无串口时对任意失败都能自动恢复；冷掉电后不丢失的失败计数/事务式完整升级。
- SMP → SMP 直接 kexec 的可靠 CPU1 唤醒。
- 四个机身 LAN 与五个 DSA LAN 索引的完整逐口映射；只确认机身 LAN1 对应 `lan3`，因此不随意删除索引或把它们错误标成五个物理 LAN。
- 默认启用 WED/HFO、完整厂商专有 PHY/Wi-Fi 优化移植、长期老化/全速 NAT 保证。
- 不检查尾部用途就统一扩容；原机扩容不是所有设备的默认布局。
- Rt Guest VLAN 的泛化部署、与任意 AP/手机的自动漫游保证。
