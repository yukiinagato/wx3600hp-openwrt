# 启动链、镜像与闪存边界

## 原厂签名与 CRC

测试设备的原厂 U-Boot 控制 DT 中，`fit_key` 要求 `sha1,rsa2048` 配置签名。不存在“直接给原厂网页上传普通 OpenWrt FIT”这一安装方式。本项目也没有 NEC 的签名私钥。

原厂 FIT 精确引用 `script@1`，而启动执行使用 `source ...:script` 缩写。实机证实保留所有原签名节点、新增 `script@0` 后，缩写会命中新入口，原有配置签名仍可验证。新入口读取后续自有脚本、选择器、Image/DTB，再使用 `booti`。

封装程序从**该使用者自己的 System2 备份**保留签名载体，并在实际 FIT / SquashFS 数据之外修正四字节 CRC，使 bootseq 的原有 CRC 覆盖范围仍匹配。不会改写 bootseq。`tools/fdt.py` 保留原属性名的字符串表偏移，打包前仍必须用原厂控制 DT 公钥和独立 `fit_check_sign` 验证；只检查“节点没变”不能代替验签。

该行为只在已测固件/启动器上成立。修改后的 carrier 必须私下从自己的备份生成，不随仓库发布；它不是常规 factory/sysupgrade 格式。

## 逻辑布局

所有偏移均是 **NMBM 逻辑偏移**，不能当作物理 NAND 地址用 `nandwrite` 直接写。

| 逻辑地址 | 长度 | 用途 |
|---|---|---|
| `0x0000000` | `0x80000` | BL2，只读保留 |
| `0x0080000` | `0x200000` | FIP，只读保留 |
| `0x0280000` | `0x80000` | Config，只读保留 |
| `0x0300000` | `0x100000` | Factory，只读保留 |
| `0x0400000` | `0x40000` | bootseq，只读保留 |
| `0x0440000` | `0x40000` | devinfo，只读保留 |
| `0x1500000` | `0x2000000` | 原厂 System1，只读保留 |
| `0x4000000` | `0x280000` | 保留原签名的启动载体 |
| `0x4280000` | `0xa80000` | SquashFS rootfs |
| `0x4d00000` | `0xbc0000` | 新 ARM64 Image |
| `0x58c0000` | `0x40000` | 两个 128KiB 启动选择记录 |
| `0x5900000` | `0x10000` | 个机 DTB |
| `0x5910000` | `0x10000` | FIT 脚本与偏移 `0x8000` 的选择程序 |
| `0x5920000` | `0x6e0000` | 首装 UBI / UBIFS 持久层 |

表中没有列出的 WDF、maperule、usercfg、userdata 等原厂区域也不允许覆盖。首装只替换既有 32MiB System2，结束于 `0x6000000`。

原机后来检查了额外尾部空白区域，才把 UBI 延伸至 `0x7800000`，约有 19.6MiB UBIFS 可用空间。**这不是本仓库的首装默认布局**。不同机器的尾部用途可能不同，不能仅改 DTB 大小就扩容。`0x7800000` 之后的物理管理保留区尤其不能触碰。小 UBI 的实际可用量会被芯片级坏块预留等开销显著压缩。

## 双系统与保护

`boot_choice.h` 定义两份带魔数、版本、序号、选择值/反码、CRC32 的记录。写入只擦除非当前有效记录所在块，回读后才正常重启，防止单次中断破坏最后选择。

启动脚本先读取选择记录；选择 OpenWrt 且易失保护标记为零才启动。启动前在 MT7622 watchdog `NONRST_REG2` 中设置 bit16；确认网络和 UBIFS 健康后才清除。保留未确认标记的暖启动会回到 System1。**这不是断电不丢失的故障计数器，也不保证任何故障都自动恢复**；冷掉电可能清掉该标记。

首次未确认启动设 120 秒回退计时。调试时 `touch /tmp/ramtest-keep` 延长当前会话；确认功能后执行 `wx-confirm`，再做软重启和至少 10 秒断电验证。不要把确认文件预置进未经验证的镜像。

“保守”按钮 GPIO95：启动后先松开，长按至少 3 秒再松开，持久保存另一系统并重启。OpenWrt 侧的服务随软件包安装；**原厂 System1 也必须单独安装按钮/SSH 服务才有对称的按钮切换**，保留原厂镜像不等于原厂自动拥有新功能。未安装时可通过可用的原厂 shell/串口选择路径恢复，不要依赖原厂按钮的旧含义。

## 处理过的故障

- 原厂 simple parser 不支持 hush 的 `if` 和脚本注释，采用 `run` 短路及独立选择程序。
- `setexpr.l` 在该 ARM64 U-Boot 读取 `ulong`，对 `0x10212024` 未对齐访问会异常；不能拿它当 32 位安全寄存器读取。
- 仅给 MTD 子分区加只读不足以阻止 NMBM 内部元数据写入；只读测试同时替换其内部 write/erase/mark-bad 回调。
- 原厂 OOB 读取曾使设备挂死；备份是 ECC 主数据及逻辑分区，不能宣称包含 OOB 的物理逐页克隆。
- SMP → SMP 的直接 kexec 未可靠唤醒 CPU1；候选从正常复位后的单核基线进入，不能用反复 kexec 代替启动验证。
- MTD 字符设备的 `fsync()` 可能返回 EINVAL；程序只接受这一特殊情况，并要求回读校验。
